# Задача: полностью заменить дизайн прошивки на систему «Мягкий» (1a)

Ты работаешь в репозитории прошивки AI-компаньона для **Waveshare ESP32-S3-Touch-AMOLED-1.75C**: PlatformIO, pioarduino 55.03.312 (Arduino Core 3), C++17, GFX Library for Arduino 1.6.9. Нужно заменить визуальный слой всех экранов и персонажа на новую систему. Логику игр, протокол, BLE, Wi-Fi, звук и датчики **не трогай**, если это не требуется для новой отрисовки.

Эталон дизайна лежит в файле `Companion 1a - Full.dc.html` (положи его в `docs/design/`). Все координаты ниже даны для экрана 466×466 с центром в (233, 233).

---

## 0. Порядок работы

1. Сначала изучи текущий код: `firmware/include/board.h`, драйвер экрана, рендер лица и эмоций, экраны в `screens/` (или там, где они лежат), меню и навигацию, шрифты. Составь карту «экран → файл».
2. Предложи план из коммитов (по одному на этап из раздела 9) и только потом начинай.
3. После каждого этапа прошивка должна собираться (`pio run`) без предупреждений в новом коде.
4. Ничего не удаляй молча: старые ассеты и шрифты удаляй только после того, как новые подключены и экран на них переведён.

## 1. Аппаратные ограничения (соблюдать везде)

- Экран CO5300 AMOLED, круглый, 466×466, QSPI, без подсветки. Вывод полосами на всю ширину, высота полосы чётная, смещение столбца 6. Цель 30–40 кадров/с. Яркость задаётся командой 0x51.
- **Фон всегда #000000**: выключенный пиксель не потребляет ток и не выгорает.
- **Только плоские заливки.** Без градиентов, альфа-смешивания и размытия: в RGB565 они дают полосы и съедают FPS. Сглаживание шрифтов допускается только предрассчитанное, на чёрный фон.
- **Яркое (белое или акцентное) занимает меньше 15% площади кадра.** Большие поля (карты, кнопки, монета, кубики) заливаются тёмным `SURFACE`, яркой бывает только обводка.
- **Безопасная зона: круг радиусом 210 px.** Текст и кнопки только внутри неё. У самого края (r 196–222) рисуются только дуги: прогресс, прокрутка, секунды.
- **Текст не меньше 22 px** (около 2 мм на 1,75″).
- **Зона касания не меньше 72×72 px** (около 7 мм), главная кнопка 92 px.
- Не больше трёх кнопок в ряд, на экране одно главное действие.
- Без бездействия 30 с яркость падает до 20%, при заряде ниже 15% экран тоже тускнеет. Датчика освещённости нет.
- Перерисовывай только изменившиеся области (dirty rects по полосам). Статичный фон экрана рисуй один раз.

## 4. Компоненты UI (`ui/components.*`)

Реализуй как функции рисования с параметрами и хит-тестом:

- `drawArc(cx, cy, r, width, startDeg, sweepDeg, color, roundCaps)`: 0° смотрит вправо, отсчёт по часовой, верх = −90°. Основа для всех колец.
- `ProgressRing`: дорожка `TRACK_2` и заливка `ACCENT` от −90°. Варианты толщины: 4 (секунды), 10 (таймер, тренировка, тряска), 16 (реакция).
- `ScrollArc`: справа у края, r 214, толщина 5, дорожка `TRACK` на 200 px длины дуги от −38°, ползунок `ACCENT` 20–60 px.
- `ButtonPrimary`: круг ⌀92, заливка `ACCENT`, текст 22–24 Onest SemiBold цветом `BG`.
- `ButtonSecondary`: круг ⌀72, обводка 2 px `INK_3`, текст `INK`.
- `ButtonPill`: высота 72, радиус 36, `SURFACE` с обводкой 2 px `INK_3` (или только обводка).
- `Card`: радиус 10–16, заливка `SURFACE`, обводка 2–3 px (`INK` для пиковых и трефовых, `ACCENT_2` для червей и бубен, `INK_3` для неактивных). Рубашка карты сплошная `TRACK`.
- `StatBar`: подпись и значение `TXT_MIN` в одну строку, под ними полоса 6 px со скруглением 3, дорожка `TRACK`.
- `List` (меню): 5 видимых строк, межстрочный шаг около 64 px. Выбранный пункт по центру Y=233 шрифтом `TXT_MENU_SEL` цветом `INK`, слева точка ⌀12 `ACCENT` (для разделов). Соседние пункты 28 px `INK_2`, следующие за ними 24 px `INK_3`. Плюс `ScrollArc`.
- `MiniFace`: персонаж, вписанный в прямоугольник заданной ширины (см. раздел 5, область 56,136 – 410,312, соотношение 354:176).

Жесты на всех экранах: свайп вниз от верхнего края возвращает назад, свайп вверх и вниз прокручивает список, тап активирует. Подсказки по жестам показываются только первые 3 с после входа на экран.

## 5. Персонаж: модель глаза

Замени текущий рендер эмоций на **параметрическую модель**. Любая эмоция задаётся параметрами для левого и правого глаза и списком накладок. Переходы между эмоциями делаются **интерполяцией параметров** за 150–250 мс с ease-out. Моргание кратковременно поднимает `t` до 0.9 каждые 3–6 с со случайным интервалом.

### Геометрия (полный экран)

```
s  - масштаб;  W = 132*s,  H = 116*s,  скругление rx = 46*s
cx = 233 - dir*85      // левый глаз dir=+1 (cx=148), правый dir=-1 (cx=318)
cy = 224
x0 = cx-W/2, x1 = cx+W/2, y0 = cy-H/2, y1 = cy+H/2
XL = x0-10,  XR = x1+10

1. Белок: скруглённый прямоугольник (x0,y0,W,H,rx), цвет INK.
2. Зрачок (если pr>0): центр (cx + px*W*0.27, cy + py*H*0.27), радиус R = H*pr, цвет BG.
   pu="heart"  - сердце размером 1.5R
   pu="spiral" - два кольца (1.5R и 0.8R, обводка 5) и точка
   pu="star"   - 4-лучевая звезда, внешний радиус 1.5R, внутренний 0.42R
3. Верхнее веко (если t>0 или a≠0): всё ВЫШЕ прямой
   y(x) = (y0 + t*H) + tan(a°)*dir*(x - cx)  закрасить BG на отрезке [XL, XR].
   a>0 опускает внутренние уголки (злость), a<0 поднимает (грусть).
4. Щека (если b>0): всё НИЖЕ параболы
   yc = y1 - b*H;  ye = yc + 0.6*b*H
   y(x) = yc + (ye - yc) * ((x - cx)/(XR - cx))^2  закрасить BG.
```

На железе удобнее рисовать построчно: для каждой строки Y внутри белка посчитать горизонтальные интервалы «белок минус веко минус щека минус зрачок» и залить их `fillRect` высотой 1. Это быстро и хорошо ложится на вывод полосами. Предрасчитай глаз один раз на кадр анимации, не на каждую полосу.

### Мини-лицо
Тот же рендер с масштабом `k = targetWidth/354` и сдвигом `(-56, -136)`. Накладки на мини-лице не рисуются.

`t=0, a=0, b=0, px=0, py=0, s=1, pr=0.17, pu=none`.
Правый глаз = левый + переопределения (колонка «R»).

## 7. Спецификация экранов

Формат: Y — верх элемента, X по центру, если не указано иное. Номера совпадают с макетом.

### Система
1. **Лицо (главный).** Полноэкранный персонаж и слой погоды. Вверху Y44 время `TXT_MIN` INK_2. Тап открывает меню, долгое касание включает «Поговорить».
2. **Меню.** Компонент `List`: Уведомления, Часы, **Лицо**, Поговорить, Питомец, Игры, Пульты, Настройки, Об устройстве. ScrollArc.
3. **Поговорить.** Кольцо r214 толщиной 6: дорожка TRACK и два сегмента ACCENT по 160 px, длина сегментов следует за уровнем микрофона (ES7210). Мини-лицо `attentive` шириной 240, Y96. «Слушаю…» 30 INK, Y236. Распознанный текст 24 INK_2 в кавычках, Y282, ширина 300, до двух строк. Кнопка «Стоп» Secondary, Y356. Во время ответа эмоция `thinking`, потом эмоция из ответа AI.
4. **Уведомления.** Y50 «1 из 3» 22 INK_2. Карточка SURFACE (x58, Y100, 350×~200, радиус 32, отступы 24/26): точка ACCENT, источник ACCENT 22, время справа INK_2; текст 26/1.32 INK, до 4 строк, дальше «…». Пилюля «Очистить всё» 180×72, Y330. Свайп по горизонтали листает уведомления.
5. **Настройки (список).** `List`, у каждого пункта подпись и значение: выбранный — подпись 24 INK_2, значение `NUM_M` INK. Пункты: Яркость, Громкость, Звук, Звуки эмоций, Микрофон, Wi-Fi, Время.
6. **Настройка значения (яркость и громкость).** Дуга r196 толщиной 12 снизу: старт 150°, развёртка 120°, дорожка TRACK, заливка INK. Подпись 28 INK_2, значение `NUM_XL` 92 «70%», ниже «гаснет через 30 с» 22. Знаки «−» и «+» 30 INK_2 у концов дуги (Y356, x58 и x408). Перетаскивание по дуге меняет значение, изменение сразу отправляется командой 0x51.
7. **Диагностика.** Y46 «Диагностика». Сетка 2×3 (x93, Y92, ширина 280, промежутки 14/24): подпись 22 INK_2 над значением `NUM_S` 30 INK. Ячейки: FPS, Батарея %, RAM, PSRAM, Звук дБ, Напряжение. Y330 строка статусов (Сенсор, IMU, PMIC, Кодек, Микрофон, BLE, Wi-Fi): «●» INK — OK, «○» ACCENT_2 — нет связи.
8. **Об устройстве.** Мини-лицо neutral шириной 100, Y66. «AI-компаньон» 30; «Прошивка X · протокол N» 22 INK_2; «BLE Companion-XXXX» (имя INK); «PIN для приложений» 22 INK_2; PIN `NUM_M` 48 ACCENT с пробелом после 3-й цифры; «AI офлайн · IP —» 22 ACCENT_2 (или INK_2, если всё в порядке).

## 8. Связь персонажа с экранами

- На игровых и служебных экранах всегда есть `MiniFace`. Его эмоция зависит от события: старт — focused/attentive, успех — happy/very_happy, ошибка — sad/annoyed, ожидание — thinking, рекорд — starstruck.
- Глобальное состояние питомца (голод, сон, одиночество) задаёт базовую эмоцию лица; игры и события временно её перекрывают и через 3–5 с возвращают.
- Ночью (22:00–7:00) и при низком заряде базовая эмоция sleepy, яркость снижена.

## 10. Критерии приёмки

- Ни одного литерала цвета вне `theme.h`. Ни одного шрифта мельче 22 px. Ни одной зоны касания меньше 72 px.
- Весь текст и все кнопки внутри круга r210, проверено отладочным оверлеем (включается флагом в `board.h`: рисует круг r210 и рамки зон касания).
- 30+ кадров/с на лице с анимацией погоды и на играх с движением (вывод FPS на экране диагностики).
- Доля ярких пикселей (INK, ACCENT, ACCENT_2) на любом статичном экране меньше 15%. Напиши утилиту, которая считает её по кадровому буферу в эмуляторе.
- Все 50 id эмоций работают через протокол как раньше. Добавь команду для эмулятора, которая по очереди показывает все эмоции и сохраняет PNG для сравнения с макетом.
- Сгенерируй обзорные PNG (как `emotions_overview.png` и `screens_overview.png`) и сравни с `docs/design/Companion 1a - Full.dc.html`. Перечисли отличия и причину каждого.
